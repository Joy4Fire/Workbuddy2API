# 推理期间管理界面卡顿与低价路由修复（0.6.1）

## 原因与实测边界

推理异步端点直接调用了同步 `get_headers`，它可能等待凭据锁、刷新 token（同步 HTTP）及写回文件；鉴权、设置查询和完整用量写入也直接等待 SQLite 共享锁。管理查询和写入使用同一连接及互斥锁，概览的多个统计查询会扫描包含大图片正文的记录页。修复前本地空闲探测：`/health` 18ms、概览约 3.65s、模型 12ms、账号 6ms。未捕获用户当时“卡死”的现场堆栈；这些是代码确认的阻塞路径与本轮实测，不把它们宣称为所有卡顿的唯一原因。

旧选号仅区分免费/未知/付费，不比较两档付费单价；模型目录虽保留了 `credits_by_region`，它没有用于选号。会话粘性直接返回原账号，也可能绕过低价通道。当前缓存的共有模型价格相同，不将旧文档中的区域差价当成今天仍然存在，也不固定假设国内或国际一定更便宜。

## 实现

- 三协议的鉴权、请求规整、token 刷新、用量写入、错误落账移到工作线程；后台计费取凭据、调度器直接写 DB、设置保存同样处理。每请求最多启动一次用量写入，避免取消线程等待后再补写重复 aborted。
- SQLite 写连接仍加锁串行化，17 个只读方法改用独立查询连接、`query_only` 和读事务，返回最近已提交的一致快照，查询结束关闭连接。账号列表只读签到快照，后台同步与显式操作负责更新。
- schema v8 通过现有迁移框架加入协议、模型、应用、时间统计覆盖索引及状态索引。只改索引，不改变表字段或记录内容；迁移前自动一致性备份。
- 动态目录的区域报价先过滤非法、负数、NaN/Inf、布尔与字符串值；缺报价不冒充零价。选号先过滤禁用、系统禁用、额度耗尽、冷却、模型负缓存，并优先使用有空闲在途名额的候选。
- 可用候选里选择最低已知区域报价。同报价（或完全没有报价）内保留免费/未知账号探索；若均为实测付费，则按每千 token 积分单价选最低值。高价只有在更低价候选不可用时接手；报价未知只在已知候选不可用时进入候选。到期紧迫度和账号优先级只在所选价格档内加权。
- 初次选号、会话复用和上游失败换号共用这条规则。同价的健康会话继续复用，出现更低价健康账号时解除旧绑定。上游原有有限重试与错误分类边界保留；不替用户更换模型。
- usage 未提供 credit 时不更新成本台账，避免把缺失计费信息学习成“免费”；明确 credit=0 仍是有效观测。已有观测继续遵循原 6h TTL。

区域目录值是标称积分倍率，实测台账是积分/千 token，两者量纲不同，因此不混成同一个数值。目录价格优先，实测值在同报价内辅助；缓存命中、输入输出比例和免费包会影响最终积分，未承诺每次实际扣费绝对最低。切换账号也可能失去原账号的 prompt cache。
