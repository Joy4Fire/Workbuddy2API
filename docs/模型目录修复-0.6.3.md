# 0.6.3 模型目录修复

发布日期：2026-10-06。数据库仍为 schema v8，无新增依赖。

## 问题与原因

目录刷新曾调用推理账号池的软区域过滤：当目标区域没有可用账号时，它会返回另一区域的账号，目录随后却被标记为目标区域，连同区域报价一起被误标。

旧插件目录也不能完整代表官方客户端的模型下拉。国际版客户端 `/v3/config` 的 CLI 白名单包含 `deepseek-v4.1-flash` 与 `deepseek-v4.1-flash-sg`，仅获取旧目录会漏掉这些模型。

## 实现

- 目录只由同区域的启用、健康账号获取；同时校验实际凭据域名与账号区域一致。推理的失败换号规则继续由账号池负责。
- 合并区域插件目录与 `/v3/config`，两路共享 CLI 白名单、禁用标志和元数据解析。同 ID 使用客户端目录元数据，保留插件专属模型。
- 按区域、账号、接口保存内存成功快照；某一路失败时保留其专属模型，全部来源失败仍触发失败退避。临时区域故障保留之前正确标记的区域缓存。
- 手动或自动停用的账号不参与目录拉取。其他区域成功刷新时，已停用区域的旧目录退出结果。
- 模型与区域报价均来自上游；新增模型没有写入静态兜底清单。账号启用状态由用户设置保持。

## 验证与升级

新增 18 项回归测试，覆盖停用、额度耗尽、冷却、实际凭据区域不一致、两路目录并集、同 ID 元数据优先级、单路失败保留缓存和全部失败退避。完整测试基线为 568 项。

本次发布已完成 Windows 与 Linux 镜像各 568 项测试、`pnpm build`（含 `vue-tsc`）、`uv lock --check`。新服务健康状态为 `healthy`，`/health` 返回 0.6.3 / schema v8；管理目录与 `/v1/models` 均能看到上述两个 DeepSeek 模型，目录区域与报价标签一致。原账号启用状态保持，8 个前端入口资源均返回 HTTP 200。此次线上验证仅查询目录，没有执行模型推理。

升级流程：运行完整测试和前端类型检查/构建，保留旧镜像回滚标签并在本地完成 SQLite 在线备份，再构建新镜像、在不挂载生产数据的临时容器中运行完整测试，最后重建服务并检查健康状态及实际模型目录。

`data/`、`auths/`、`.env` 和 `.tmp/` 保留在本地，Git 与 Docker 构建上下文均排除这些目录和文件。公共说明不包含账号、凭据、应用密钥、数据库副本或用户对话。
