# 参考项目更新核验与吸收（2026-10-02）

## 项目定位与边界

Workbuddy2API 是单用户 FastAPI 网关，以 WorkBuddy/CodeBuddy 为上游，统一提供 OpenAI Chat、Responses、Anthropic Messages 三协议。现有系统包含国内/国际双区域账号池、会话粘性、错误分类处置、SQLite 全量用量记录、签到与积分任务，以及 Vue 3 管理界面。

本轮从本地 HEAD `9946a6b` 开始，工作区原本干净，464 项原有测试通过。比较对象是 ReferenceProject 的 **12 个本地快照与各仓库远端默认分支 HEAD**，不是仅比较发布日期。远端提交下载到本项目 `.tmp/references/` 的独立 Git 快照，原参考项目目录保持原状。

## 未吸收的变化与理由

- Buddy2api 的一键 `git pull`、安装依赖和自重启不匹配当前 Docker 挂载部署；还会改变带本地改动的工作区，因此只提供版本查询与手动升级说明。
- cli2api 的 Codex、Qoder、Trae、Command Code、Devin 通道需要独立认证、额度与原生协议，超出 WorkBuddy 专用网关定位，不作为本轮隐含需求。
- cli2api 的坏 JSON 工具历史自动剔除会丢弃工具调用与结果；没有直接复制该策略，避免改变用户传入的工具语义。
- 新资源监控卡片与 worker 内存限额依赖对方 worker 架构；本项目没有对应 worker，不机械加入。
- DSH 模型目录变化与本项目已评估的 `/v3/config` 取舍不同，不替换当前已验证的区域目录路径，也不引入静态模型列表。
- 不改现有签到/旅行/领奖开关，不新增自动通知，不消耗补签卡，不调整账号优先级或管理鉴权。
