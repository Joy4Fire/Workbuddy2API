# 0.6.4：修复 Docker bridge 部署的局域网访问

对应 [GitHub issue #1](https://github.com/Joy4Fire/Workbuddy2API/issues/1)。schema 仍为 v8，无数据库迁移或新增依赖。

## 问题与修复

此前 Host 回环白名单无条件作用于所有请求，即便设置 `ADMIN_TOKEN`，通过宿主机局域网 IP 打开 `/` 也会返回 403「Host 不被允许」，请求尚未进入管理鉴权。

- 设置 `ADMIN_TOKEN` 后允许通过 IP 或域名加载 WebUI 与静态资源；`/admin/*` 仍严格校验 Token，`/v1/*` 仍使用应用 API Key。
- 未设置 Token 时继续限制回环 Host，保留 DNS rebinding 防护及 Docker 端口映射的本机访问行为。
- 回环 Host 支持 `[::1]` 与 `[::1]:8787`；旧实现按冒号拆分会误拒绝 IPv6。
- Compose 从宿主机环境变量或项目 `.env` 自动透传 `ADMIN_TOKEN`。此前示例仅有注释，单独修改宿主机 `.env` 不会把 Token 传入容器。

## 升级

在项目 `.env` 中配置 `ADMIN_TOKEN=<随机长字符串>`，执行：

```sh
git pull
docker-compose up -d --build --force-recreate
```

保持 bridge 网络与现有数据卷即可。浏览器打开 `http://<宿主机局域网IP>:8787/`，在右上角「Token 管理」填入相同 Token。直接运行 Python 服务时，还需设置 `HOST=0.0.0.0`。

## 验证范围

新增六项隔离回归测试，覆盖局域网 IP/域名/IPv6 页面与静态资源、两种管理鉴权头、缺失与错误 Token、无 Token 的远程 Host 拦截、Docker 网桥客户端的回环访问、推理 API Key 校验及跨域限制。

完整 574 项测试通过，`uv lock --check --offline` 通过。0.6.4 镜像构建成功；使用空临时数据卷分别启动有 Token、无 Token 的 bridge 容器，经宿主机映射端口发送带局域网 Host 的真实 HTTP 请求，页面、已构建静态资源与上述鉴权边界均通过。未使用另一台局域网设备或用户的具体网络环境进行验证。
